# Battlesnake · ДЗ № 2

Бот на Go для Duels, Standard, Royale и Constrictor. Он отсеивает ходы, которые ведут к гибели, затем оценивает пространство, угрозы со стороны соперников и доступность еды. В Constrictor бот учитывает, что хвост остаётся на месте, и сильнее штрафует ходы с малым запасом пространства.

## Запуск

Нужен Go 1.22 или новее.

```sh
GOMAXPROCS=1 HOST=127.0.0.1 PORT=8080 go run .
curl -fsS http://127.0.0.1:8080/duels
```

Базовые пути для регистрации — `/duels`, `/standard`, `/royale`, `/constrictor`. На каждом доступны `GET /`, `POST /start`, `POST /move` и `POST /end`. Например, арена отправляет игровой запрос на `POST /duels/move`. Корневой URL также можно использовать для локальных матчей. Явный префикс Standard сохраняет этот профиль, когда остаются две змейки.

```sh
GOMAXPROCS=1 go test ./... -count=1
go test -race ./...
docker build -t battlesnake-hw2 .
docker run --rm --cpus=1 -p 127.0.0.1:8080:8080 battlesnake-hw2
```

## Локальные серии

В отдельных терминалах из каталога проекта запустите бота, затем локальных контрольных соперников.

```sh
GOMAXPROCS=1 HOST=127.0.0.1 go run .
```

```sh
python3 tools/reference_snakes.py --port 8081
```

Соберите Battlesnake CLI v1.2.3 для воспроизводимого распределения стартовых позиций. Скрипт меняет только локальный порядок назначения слотов. Игровые правила остаются официальными. Условия теста фиксируются seed и перестановкой слотов, а CSV содержит исход, место, задержку и причину выбывания.

```sh
python3 tools/build_series_cli.py ./bin/battlesnake
go run ./cmd/series -cli ./bin/battlesnake -mode duels \
  -candidate http://127.0.0.1:8080/duels \
  -opponent http://127.0.0.1:8081/space \
  -seed-start 101 -seeds 20 -replays ./replays
```

Для Duels можно подставить `/greedy` или `/center` вместо `/space`. Для Standard, Royale и Constrictor укажите нужный режим и соответствующий путь у кандидата, затем передайте три флага `-opponent` с путями `/greedy`, `/space`, `/center`. Серия запускает каждый seed по одному разу на каждый стартовый слот. Время в CSV — максимум среди кадров, где кандидат ещё жив. Движок округляет его до миллисекунд, а ход выбывания может отсутствовать в этих данных. Утилита возвращает ошибку при технических сбоях и записывает такие партии в CSV. Без `-replays` файлы партий удаляются после завершения.

### Контрольная серия

Результаты на 20 отложенных seed, 101–120. В Duels сыграно 40 партий против каждой из трёх локальных стратегий. В остальных режимах они играли вместе, всего по 80 партий.

| Режим | Победы | Поражения | Ничьи |
| --- | ---: | ---: | ---: |
| Duels | 115 | 4 | 1 |
| Standard | 73 | 7 | 0 |
| Royale | 63 | 15 | 2 |
| Constrictor | 39 | 36 | 5 |

В Constrictor экспериментальная оценка наибольшей области после закрытия прохода дала 27 побед из 56 против 22 у базовой версии на seed 1–14. На отложенных seed она выиграла 32 партии из 80 против 39 у базовой версии. Поэтому в боте оставлена базовая оценка. Все партии Constrictor из таблицы проведены на карте без еды. Контрольные соперники входят в этот проект. ## Публикация

На Render создайте Web Service из репозитория проекта с окружением Docker и проверкой доступности по `/`. Render выдаёт базовый HTTPS-адрес. В Arena зарегистрируйте отдельную запись для каждого профиля и подключите её к соответствующему рейтингу. Проверьте, что первый матч в каждом режиме проходит без таймаутов. [Документация Render](https://render.com/docs/docker) · [Рейтинги Battlesnake](https://arena.battlesnake.com/leaderboards)

Если Render начнёт регулярно засыпать между матчами или ответы приблизятся к лимиту арены, запасной вариант — круглосуточный VPS. На нём можно развернуть тот же контейнер за HTTPS-прокси и заменить адреса профилей в Arena.
