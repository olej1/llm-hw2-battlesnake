# Battlesnake · ДЗ № 2

Бот на Go для Duels, Standard, Royale и Constrictor. Он отсеивает ходы, которые ведут к гибели, затем оценивает пространство, угрозы со стороны соперников и доступность еды. В Constrictor бот учитывает, что хвост остаётся на месте, и сильнее штрафует ходы с малым запасом пространства.

## Запуск

Нужен Go 1.22 или новее.

```sh
GOMAXPROCS=1 HOST=127.0.0.1 PORT=8080 go run .
curl -fsS http://127.0.0.1:8080/duels
```

Базовые пути для регистрации — `/duels`, `/standard`, `/royale`, `/constrictor`. На каждом доступны `GET /`, `POST /start`, `POST /move` и `POST /end`. Например, арена отправляет игровой запрос на `POST /duels/move`. Корневой URL также можно использовать для локальных матчей. Явный префикс Standard сохраняет этот профиль, когда остаются две змейки.

```sh
GOMAXPROCS=1 go test ./... -count=1
go test -race ./...
docker build -t battlesnake-hw2 .
docker run --rm --cpus=1 -p 127.0.0.1:8080:8080 battlesnake-hw2
```

## Эксперимент с тактикой Duels

Первый кандидат для стандартного Duels проверял одновременные ходы обеих змей на два хода вперёд. Он меняет выбор эвристики, если поиск находит более безопасный исход или вынужденную победу на этом горизонте. При исчерпании 8 мс остаётся ход эвристики.

| Локальная проверка | Базовый бот | Кандидат |
| --- | ---: | ---: |
| Друг против друга, 250 партий с перестановкой слотов | 120 побед | 121 победа |
| Против Snork Mobility, отложенные seed 101–120 и 701–765 | 78 / 170 | 87 / 170 |
| Против Snork Tree, отложенные seed 501–508, бюджет соперника 15 мс | 9 / 16 | 10 / 16 |

В прямом сравнении также было 9 ничьих. Вариант со штрафом за отсутствие запасного выхода выиграл 46 из 250 партий у базового бота и был отброшен. Финальный кандидат остался экспериментальным, поскольку прямые матчи не показали устойчивого преимущества. На арене продолжает играть опубликованная базовая версия.

### Территория и третий ход

Проверены два изменения. Оценка территории учитывает первое съеденное яблоко, задержку освобождения сегментов и приоритет более длинной змейки при одновременном подходе к клетке. Из поиска пути к еде исключаются проходы, которые противник может опередить. Третий ход рассчитывается, когда головы находятся на расстоянии не более шести клеток по Манхэттену. При исчерпании бюджета возвращается результат законченного поиска на два хода.

| Вариант | Победы / поражения / ничьи в очных матчах с опубликованным ботом | Победы против Snork Mobility |
| --- | ---: | ---: |
| Территория, без тактического поиска | 126 / 151 / 3 | 50 / 110 |
| Третий ход, базовая территория | 305 / 288 / 7 | 41 / 110 |
| Территория и третий ход | 131 / 148 / 1 | 51 / 110 |

На тех же стартах против Snork базовый бот выиграл 33 из 110. Очные серии используют seed 101–140, 1001–1050 и 2001–2050 с перестановкой двух слотов. Для третьего хода добавлены отложенные диапазоны 3001–3080 и 4001–4080. В серии против Snork использованы seed 701–720 и 1201–1235.

Мягкие версии оценки территории также уступили базовой версии в очных матчах. Вариант, который повышал ценность доступной еды при отставании по длине, выиграл 160 матчей, проиграл 158 и сыграл вничью 2 на двух отложенных сериях. Результат разошёлся по наборам стартов.

В этой серии был выбран третий ход. Чтобы повторить раннюю оценку территории, локально включите `useDuelTerritory` в `strategy.go`. Для проверки территории без поиска запустите с `-duel-depth=0`.

### Четыре следующих эксперимента

В выбранной конфигурации Duels ищет до пяти ходов, когда головы не дальше четырёх клеток по Манхэттену. В концовке Standard поиск ограничен четырьмя ходами и включается после выбывания всех соперников кроме одного. Для глубокого поиска действует бюджет 12 мс. При отмене сохраняется последняя законченная итерация. Позиционная оценка учитывает длину, выходы, ближайшее доступное пространство, здоровье и еду. На глубоких уровнях дерево использует видимую еду, поскольку будущее появление еды случайно.

| Эксперимент | Результат локальных матчей |
| --- | --- |
| Duels, глубина 5 только в радиусе 4 | 224 победы, 35 поражений, 1 ничья против опубликованной базовой версии. Против Snork Mobility 80 побед из 130, у трёхходового контроля 48 |
| Фазовые веса Duels | Первый вариант 83 победы, 83 поражения, 4 ничьи против трёхходового контроля. Второй вариант 86 побед, 80 поражений, 4 ничьи, но меньше побед против Snork |
| Защита от самозапирания | 83 победы, 83 поражения, 4 ничьи против трёхходового контроля. Против Snork 49 побед из 112, у контроля 48 |
| Концовка Standard, до четырёх ходов | 157 побед из 280 на отложенных стартах, у контроля 142. В обоих наборах улучшились доля побед и среднее место |

Точная финальная сборка на новых стартах выиграла 111 из 140 дуэлей у трёхходового контроля. В Standard на новых стартах она выиграла 99 из 200 матчей против 90 у контроля. В Docker с лимитом в один CPU проверено по 40 HTTP-ответов каждого режима. Максимум для Duels составил 7,35 мс, для Standard 2,30 мс.

Ранний поиск до пяти ходов на большем расстоянии дал 205 побед из 260 против опубликованной версии и 50 из 130 против Snork. В серии шестой глубины под параллельной нагрузкой был один технический сбой. Фазовые веса и защита от самозапирания доступны для опытов, по умолчанию они выключены.

```sh
go run . -duel-depth=3 -standard-endgame=false
go run . -duel-depth=5 -duel-search-radius=4 -standard-endgame=true
```

Первая команда запускает трёхходовой контроль. Вторая включает выбранную конфигурацию. Диапазоны для очных Duels с опубликованным сервером `9101–9165` и `10101–10165`. Для сравнения со Snork `9301–9330` и `11301–11335`. Для отложенных Standard `9101–9130` и `10101–10140`. Соперники в Standard — исходная опубликованная версия, `greedy` и `space`. Для отдельных опытов можно указать `-phase-weights=1`, `-phase-weights=2`, `-tail-safety` или `-duel-search-radius=0`.

### Маршруты Constrictor в версии 0.2.1

В Constrictor бот сравнивает, сколько клеток можно посетить одним маршрутом в закрытой области. Поиск использует до 384 раскрытий на ход-кандидат и меняет исходный ход, если на другой ветке найден маршрут длиннее верхней оценки для исходной ветки. Проверка применяется, когда соперники не могут попасть в рассматриваемые области при текущей конфигурации поля.

На 48 уникальных стартах официальной карты 11×11 без еды бот выиграл 19 матчей против 15 у версии 0.2.0 в группе с 0.2.0, Space и Center. В группе с Greedy, Space и Center обе версии выиграли по 20 матчей. Проверка использует seed 27101–27132 и четыре стартовых слота. Регрессионный тест воспроизводит ход 17 партии с seed 27101 в третьем слоте, где два направления ведут в области одинаковой площади с разной длиной проходимого маршрута.

### Защита выхода и проходов в версии 0.2.2

В Duels при преимуществе минимум в два сегмента и малом числе выходов проверяем до семи ходов. Бот меняет исходный ход, если видит лучший тактический исход с продолжением игры. При исчерпании 12 мс остаётся исходный ход. На позиции с перевесом 26:16 поиск выбирает выход из коридора. В локальных сериях победы выросли с 32 до 33 из 60 против Snork Mobility и с 39 до 41 из 48 против двухходового бота.

В Constrictor просчитываем до четырёх ходов по проходам, куда соперник может успеть раньше. Исходный ход меняется, если альтернативный маршрут даёт как минимум два дополнительных хода в модели и сохраняет уровень риска первого шага. На 48 уникальных расстановках в смешанной серии победы выросли с 16 до 18 и среднее место улучшилось с 1,958 до 1,875. Против Greedy, Space и Center на 44 уникальных расстановках получилось 20 побед против 19 у контроля.

## Открытые соперники для Duels

Для сравнения версий используем [Snork](https://github.com/wrenger/snork/tree/76bec0c9c76b31b209fbeb8e409bb3e4c9133eb2) под MIT. Mobility быстро оценивает позицию, а Tree моделирует ответы соперника. Они запускаются отдельно от бота и подключаются через флаг `-opponent`.

```sh
git clone https://github.com/wrenger/snork.git /tmp/battlesnake-snork
git -C /tmp/battlesnake-snork checkout 76bec0c9c76b31b209fbeb8e409bb3e4c9133eb2
docker build -f tools/opponents/snork.Dockerfile -t battlesnake-snork-local /tmp/battlesnake-snork
docker run --rm --cpus=1 -p 127.0.0.1:8082:5001 battlesnake-snork-local
```

Для профиля Tree добавьте к команде запуска `--latency 485 --config '{"Tree":{}}'`. При таймауте движка 500 мс это оставляет сопернику 15 мс на поиск. Укажите `-opponent http://127.0.0.1:8082` в команде локальных серий. Запустите серию отдельно для исходной и новой версий с теми же seed и обоими стартовыми слотами.

Дополнительные источники для разбора алгоритмов — [Battlesnake Snake Zoo](https://github.com/BattlesnakeOfficial/snake-zoo), [решения coreyja](https://github.com/coreyja/battlesnake-rs) и [POG](https://github.com/calvinl4/battlesnake-winter-2022/tree/519588f2cb2a768a363c148a7a52b59f8826ef91). POG не вошёл в подсчёт результатов, так как движок зафиксировал некорректные ответы `/move`.

## Локальные серии

В отдельных терминалах из каталога проекта запустите бота, затем локальных контрольных соперников.

```sh
GOMAXPROCS=1 HOST=127.0.0.1 go run .
```

```sh
python3 tools/reference_snakes.py --port 8081
```

Соберите Battlesnake CLI v1.2.3 для воспроизводимого распределения стартовых позиций. Скрипт меняет только локальный порядок назначения слотов. Игровые правила остаются официальными. Условия теста фиксируются seed и перестановкой слотов, а CSV содержит исход, место, задержку и причину выбывания.

```sh
python3 tools/build_series_cli.py ./bin/battlesnake
go run ./cmd/series -cli ./bin/battlesnake -mode duels \
  -candidate http://127.0.0.1:8080/duels \
  -opponent http://127.0.0.1:8081/space \
  -seed-start 101 -seeds 20 -replays ./replays
```

Для Duels можно подставить `/greedy` или `/center` вместо `/space`. Для Standard, Royale и Constrictor укажите нужный режим и соответствующий путь у кандидата, затем передайте три флага `-opponent` с путями `/greedy`, `/space`, `/center`. Серия запускает каждый seed по одному разу на каждый стартовый слот. Время в CSV — максимум среди кадров, где кандидат ещё жив. Движок округляет его до миллисекунд, а ход выбывания может отсутствовать в этих данных. Утилита возвращает ошибку при технических сбоях и записывает такие партии в CSV. Без `-replays` файлы партий удаляются после завершения.

## Публикация

На Render создайте Web Service из репозитория проекта с окружением Docker и проверкой доступности по `/`. Render выдаёт базовый HTTPS-адрес. В Arena зарегистрируйте отдельную запись для каждого профиля и подключите её к соответствующему рейтингу. Проверьте, что первый матч в каждом режиме проходит без таймаутов. [Документация Render](https://render.com/docs/docker) · [Рейтинги Battlesnake](https://arena.battlesnake.com/leaderboards)

Если Render начнёт регулярно засыпать между матчами или ответы приблизятся к лимиту арены, запасной вариант — круглосуточный VPS. На нём можно развернуть тот же контейнер за HTTPS-прокси и заменить адреса профилей в Arena.
